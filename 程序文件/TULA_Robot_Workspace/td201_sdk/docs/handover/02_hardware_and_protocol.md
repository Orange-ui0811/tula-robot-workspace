## 硬件角色

| 名称 | 是什么 | 不是什么 |
|---|---|---|
| TD-201 | 双轴数字位置/速度控制及驱动板卡 | 不是机械转台 |
| TULA50 / TULA70 | TULA执行机构/电机系列；转台资料分别列两只TULA50或TULA70 | 不是PC SDK，也不要与TD-201控制板混称 |
| MDT50 | 由TULA50驱动的机械转台，资料含MDT50-1802 | 两只执行机构不代表两个独立转台自由度 |
| HDT70 | 由TULA70驱动的中空机械转台，资料含HDT70-H102 | 不能仅凭名称确定现场行程和版本 |

资料有“驱动器/电机”混用术语，本文按控制器、执行机构、机械平台区分。

```text
PC → Windows COM / USB Serial → TD-201 UART/MCU
                                      ↓
                              PID/IIR → PWM → Motor Driver
                                                   ↓
                                           TULA执行机构
                                                   ↓
                                           MDT50/HDT70转台
                                                   ↓
                       QEI ← 差分输入 ← 增量编码器A/B/Z
```

框图依据技术规格第2页，属于控制板内部机理，不是本仓库实现的固件：

- A/B是正交增量信号，供计数和判断方向；Z是参考标记/索引。
- QEI是正交编码器接口，把反馈信号转换为控制器可用的位置计数。
- PID和IIR承担板内控制和滤波；C SDK提供设置命令，不执行板内控制算法。
- PWM产生内部驱动波形/占空比控制，PC不是逐个发送PWM脉冲。
- Motor Driver将控制信号变成执行机构驱动；框图含升压DC/DC。板卡输入5V与驱动输出16～35V不是同一电压，不能据此自行接线。

## 通信接口：支持与实际使用分开

资料列USB Serial、RS-232、RS-485和外部脉冲/方向。技术规格第3页及驱动器截图提及FT232R；外层交接说明当前是USB转串口。软件在Windows端只看到COM口，C层调用CreateFileA/ReadFile/WriteFile。

本次没有检查实物，不能确认现场是否接外置USB-RS485转换器。RS-232/RS-485电气、模式/地址开关、线缆均待硬件人员确认。脉冲/方向模式走外部信号口，不是当前ASCII路线。旧CDM安装包的现代Windows兼容性和已装驱动版本也待确认。

## ASCII帧与示例

协议规定请求起始为 `>`，回复起始为 `<`，结束是回车 `\r`（0x0D）；这里的STX/ETX是字段名称，不是额外发送0x02/0x03。

```text
请求：> + 两位轴号 + 命令 + [空格 + 参数] + \r
回复：< + 两位轴号 + 命令或status字段 + [参数] + \r
```

命令表中的真实格式，令axis=1；`\r`表示一个回车字节：

| 请求 | 回复形式/含义 | 表格位置 |
|---|---|---|
| `>01ma 1000\r` | `<01ma 1000\r`，目标回显，不代表已到位 | G3/H3 |
| `>01mr 10000\r` | `<01mr <目标计数>\r`；请求是偏移，回复是目标位置 | G4/H4 |
| `>01hm\r` | `<01hm\r`，发起回零，不等于回零完成 | G5/H5 |
| `>01st\r` | `<01st\r`，停止请求回复 | G7/H7 |
| `>01cp\r` | `<01cp <当前计数>\r`，位置反馈 | G14/H14 |
| `>01al\r` | `<01status <十进制报警> (<十六进制报警>)\r` | G15/H15 |

尖括号包围的“目标计数”等是本文占位符，不是字面协议。以第一行为例：`>`请求、`01`地址、`ma`命令、空格0x20、`1000`计数、0x0D结束，对应C层format_cmd()。

当前td201_move_absolute()把resp传NULL，只发送ma，不等待上述回显。协议支持回复不意味着所有API都接收回复。

### 串口参数和回复处理

- 默认115200 bps、ASCII、8数据位、1停止位、无校验。
- Windows从GetCommState读取DCB后设置波特率/数据位/停止位/校验位，没有显式重置全部软硬件流控标志，不能宣称代码已确定禁用所有Windows流控。POSIX显式关闭IXON/IXOFF与CRTSCTS。
- send_and_recv()发前清空RX，按轴号和命令匹配；al兼容NNal及NNstatus。不匹配帧丢弃，在期限内重试。
- 实际宏：TD201_TXN_TIMEOUT_MS=12、TD201_LINE_TIMEOUT_MS=50、TD201_POLL_MS=100。注释中的“5ms”“微秒级非阻塞”不是现实现的性能证明；ReadFile和系统调度仍可能阻塞，不能承诺严格12ms实时上限。
- TD201_ERR_TIMEOUT、TD201_ERR_PROTOCOL、I/O错误是软件返回码；MOTOR_RUNNING等是控制器状态位，两类错误要分开排查。

## 轴ID与位置单位

TulaRobot(active_axes=[1,2])创建协议地址1、2的两个软件轴，共用一个TD201MotorBus。顺序决定action元素映射；不是轴数组下标0/1。td201_axis_bind()保存axis_id，format_cmd()用%02u形成01/02。

协议资料写地址01～32；当前C检查允许1～99。C测试还绑定轴3为Z轴；TD-201资料说明单板双轴，不能仅凭绑定成功认定有第三硬件通道，绑定只做软件检查。第三轴来源、控制器地址组合及菊花链现场拓扑待确认。

| 来源 | 数值/处理 |
|---|---|
| 转台资料 | MDT50/HDT70列0.005°/脉冲，ABZ |
| C源码 | TULA50_PULSES_PER_DEGREE=200.0 |
| Python源码 | TD201Motor.PULSES_PER_DEGREE=200.0 |
| 换算 | counts=degree×200，degree=counts/200，目标采用正负对称四舍五入 |

1/0.005=200在数值上对应，但是否适用于每个轴、固件、编码器倍频和直线平台仍须确认。分辨率不是重复定位精度。通用C物理量API接收pulses_per_unit；C测试轴3的1000 pulses/mm是可输入覆盖的默认示例，不是平台验收参数。

## 回零和状态

增量编码器反映变化，掉电后不能单凭计数恢复机械绝对参考。资料写上电状态0x1000；hm建立参考。Z标记、机械限位与具体回零方向需现场确认，不能把“置软件零点”与回零等同。

| 状态 | 含义 | 当前实现 |
|---|---|---|
| 0x8000 MOTOR_RUNNING | 运行中 | 绝对运动等待判停 |
| 0x1000 HOME_MISSING | 原点未知 | home_wait要求其与运行位均清除 |
| 0x0008 POSITION_ERR | 位置偏差 | 不在fatal mask；不表示总能忽略 |
| 0x0010/0x0004/0x0001 | 编码器/Z相/过温 | TD201_FATAL_MASK |
| 0x0100/0x0080/0x2000 | 命令/参数/调谐错误 | 有解析打印，但不都纳入fatal mask |

td201_move_absolute_wait()先判断“不运行则成功”，然后才判断运行期间fatal；没有独立停后POSITION_ERR和最终位置容差检查。TulaRobot.set_angles()读取位置判容差，不检查完整状态字，超时返回False。外层pyserial的“运行中暂容、停后重查POSITION_ERR”不是本工程能力。
