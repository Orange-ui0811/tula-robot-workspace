# TULA / TD-201 现场实机验收计划

本计划由获授权的现场人员执行。当前软件基线为 LeRobot **0.6.2**（`ba83e4cf43737e2665be0aafcb5f513b83c7d0f3`）、Tula 插件 **0.1.0**、工作区 `.venv` 内的 **CPython 3.12.13 x64**。两个项目均为本地 editable 安装，官方插件发现、配置解析、工厂创建和 13 项无硬件测试已通过。**实机通信、运动、停机和周期性能尚未验收**，本表不预填通过。

## 开始前：准备设备、记录参数、确定放行人

准备 TULA 电机、TD-201 驱动/控制器、Windows x64 电脑、与现场电气接口匹配的 USB 转串口设备（或控制器自带 USB 串口）及对应驱动。按本机型接线图确认电源、接口模式、线缆、机械安装、负载支撑和运动净空。不可仅凭插头或 COM 号推断 RS-232、RS-485 等电气类型，不得按示例电压或默认值接线。技术资料入口：[硬件与协议](td201_sdk/docs/handover/02_hardware_and_protocol.md)、[SDK 测试与安全](td201_sdk/docs/handover/06_testing_and_safety.md)。

**放行规则：** A → B → C → D → E → F。A 阶段就要按现场规程确认独立停机手段可用，不把首次可用性确认拖到 F。C 前若尚未建立可信参考点，不准用绝对目标试动：暂停 C，由负责人按 D 的专项流程单独批准并完成必要的单轴回零，再返回 C。C、D、E 和涉及真实设备的异常/停机验证须有现场监护；每阶段签字后才进入下一阶段。轴 ID、方向、限位、回零或停止方式未确认，不得运动；机械范围不明，不得双轴运动。出现异常报警、通信丢失、方向错误、意外位移或不能可靠停机，立即终止下发，按现场规程停机，确认实物安全并记录；不得自动重试或带故障升级测试。

**关闭串口、退出程序、Ctrl+C、软件显示已断开，都不等于电机停止。** 软件 `stop()` / `td201_stop()` 只是通过当前通信链路发停止请求，不能替代急停，也不能以函数返回作为物理停机证明。

2. 获准连接实物后，在**工作区根目录 PowerShell**执行 `.\.venv\Scripts\python.exe -I -B` 进入 Python 交互终端。以下代码只加载**插件随附的** TD-201 DLL，打开现场确认的端口，逐轴查询报警/状态字和原始位置；不回零、不使能、不写位置、不改参数。按提示填实际参数，不枚举未知地址。可将整个 `exec(...)` 块粘贴进交互终端。用完退出交互终端；退出不是停机操作。

```python
exec("""
from lerobot_robot_tula.td201_driver import TD201Driver, PULSES_PER_DEGREE

port = input('已确认的 COM 端口：').strip()
baud = int(input('已确认的波特率：'))
axes = [int(v) for v in input('已确认的轴 ID（空格分隔）：').split()]
if not port or baud <= 0 or not axes or len(set(axes)) != len(axes) or not all(1 <= a <= 32 for a in axes):
    raise ValueError('请核对端口、波特率和轴 ID')
driver = TD201Driver(port, baud)
try:
    driver.connect()
    for axis in axes:
        driver.bind(axis)
        try:
            status = driver.read_status(axis)
            counts = driver.read_counts(axis)
            print(f'axis={axis} status=0x{status:04X} counts={counts} software_deg={counts / PULSES_PER_DEGREE}')
        finally:
            driver.unbind(axis)
finally:
    driver.close()
""")
```

4. 可选：若需独立验证 SDK 本身，且现场已备有确认来源的 C 诊断 EXE、实际速率是 115200、确认该工具针对的轴 1/2，先关闭 Python 会话。仅在 **`td201_sdk` 根目录 PowerShell**执行 `.\tests\test_hardware_c.exe`，输入经确认的串口，选 **1** 查询，再选 **0** 退出。没有该 EXE 或轴/速率不匹配就跳过此交叉检查，记录原因，不为此乱试其他菜单。构建和调试说明见 [SDK README](td201_sdk/README.md)。

## 阶段 D：物理回零与动作限位（分开验收）

1. **LeRobot Calibration 不等于 Homing。** 当前插件的 `calibrate()` 不执行主机标定，也不做物理回零；`is_calibrated` 为真不表示实机有原点。`is_homed` 是最近状态查询的快照，不是实时证明。
2. 核对本机型回零方向、参考点、机械路径、超时、负载支撑和中止方案后，单独批准回零。使用 C 的**单轴配置**在同一交互会话连接但不发位置目标，然后由监护人确认后执行 `robot.home(timeout_ms=int(input("已批准的回零超时（毫秒）：")))`。这是**真实运动**，调用 `td201_home_wait()`；对多轴配置会按配置顺序对**全部轴**请求回零，不要拿双轴配置验证单轴回零。动作软件限位不会约束物理回零路径。回零后查状态、位置并核对实际参考位置，记录方向、耗时及偏差；异常按现场规程中止，不直接重试。
3. **非法输入只在 Mock 中注入。** 在工作区根目录用 B 的测试命令，查验 `test_bad_frame_has_no_partial_write`（NaN、Inf、越界等整帧拒绝）、`test_limits_not_configured_disables_motion` 和 `test_sdk_range_rejects_entire_frame_before_writes`；不把故意非法的目标发给实机。实机只在批准范围内以已验证的小步核对软件限位配置与现场范围一致；不靠撞机械限位证明边界，不运行 C 菜单 4。硬件限位/防护功能如需独立认证，按厂商及现场批准规程，另行记录，不以软件拒绝代替。

## 阶段 E：双轴映射与连续下发（真实运动，须专项放行）

1. 两轴均须通过各自单轴、参考点和停止检查。确认全路径无轴间干涉、碰撞和线缆拉扯，审批双轴测试范围、有限帧数、间隔、误差及超时标准。结束上一会话并释放串口后，在**工作区根目录**重新运行 `.\.venv\Scripts\python.exe -I -B`。在新终端输入下列配置代码（连接和读回，不下发运动）。`joint_1`、`joint_2` 是本例的关节键，不代表实物地址；输入各自确认过的 ID 和批准限位。

```python
from lerobot_robot_tula import TulaRobot, TulaRobotConfig
port = input("已确认的 COM 端口：").strip()
baud = int(input("已确认的波特率："))
a1, a2 = map(int, input("joint_1 和 joint_2 的轴 ID（空格分隔）：").split())
l1, h1 = map(float, input("joint_1 批准的下限 上限（度）：").split())
l2, h2 = map(float, input("joint_2 批准的下限 上限（度）：").split())
cfg = TulaRobotConfig(port=port, baudrate=baud, axes={"joint_1": a1, "joint_2": a2}, action_limits_deg={"joint_1": (l1, h1), "joint_2": (l2, h2)})
robot = TulaRobot(cfg)
robot.connect(calibrate=False)
print(robot.action_features, robot.get_observation(), "参考状态快照：", robot.is_homed)
```

   核对 features、两轴观测和状态，无异常才下发。先分别验证两轴映射，每次只改变待验关节的目标，另一关节目标设为经审批的当前安全位置。**双轴完整动作帧仍会给两轴下发目标**，不能当成单轴隔离。
2. 用 `robot.send_action(frame)` 执行一帧已审批的绝对目标，`frame` 必须恰好包含两轴对应的 `<关节名>.pos`，值为度；不要用未审批示例数字。先单帧低速验证，再按批准间隔逐帧测试短序列。每帧核对前一帧结果，任何异常立即停止后续下发。该 API 先查各轴状态，再按配置顺序发命令，并非原子同步写；一轴失败时前一轴可能已收到目标。
3. 在**同一 Python 终端**，单帧可用下列计时方式；`frame` 只使用现场已审签目标。分别记录下发耗时、观测读取耗时、相邻帧实际间隔（连续记录 `t0`）和实物到位时间；区分程序耗时与机械响应。现场确认判定标准，记录异常帧、超时、最大/典型延迟。不要用旧压测或 `move_and_wait()` 的默认 50 Hz 到位轮询作为已支持 50 Hz 周期控制的证据。

```python
from time import perf_counter
g1, g2 = map(float, input("本帧批准的两个绝对目标（度，空格分隔）：").split())
frame = {"joint_1.pos": g1, "joint_2.pos": g2}

accepted = robot.send_action(frame)
t1 = perf_counter()

print(accepted, obs, "发送毫秒", (t1 - t0) * 1000, "读回毫秒", (t2 - t1) * 1000)
```

## 阶段 F：连接异常、通信超时和停机

1. **仅在无运动、负载已支撑、独立停机手段可用时注入故障。** 可由授权人员用已知独占方式复现端口占用，再用 B 的只读入口尝试连接，记录连接错误、释放占用后的复测。若台架有已批准的方式在静止安全状态模拟无回复，可在该状态下执行只读查询，记录超时/协议错误；没有安全方式就标记未测，不通过随意拔线、拔电机线、改波特率或让设备运动中失联来制造故障。
2. 正式插件的 I/O 失败测试应在同样安全条件下从 `connect()` 或 `get_observation()` 触发，记录原始异常、`is_connected`、串口能否在故障排除后重新打开。SDK 软件错误码与设备报警字分别记录（例如源码定义 I/O 为 3、超时为 4、协议错误为 5；均不是实机停机状态）。插件会尝试清理资源；若已断连，不能再指望同一对象发送 `stop()`。不要自动重连或继续发动作。两轴中途失败只在 Mock 注入，除非另有专项批准。
3. 在现场批准工况下执行正常停机、急停或断电及恢复规程，实测停止时间、负载是否移动、驱动器状态和复位要求。**先确认实际停止、机械安全，再断开串口**；观察断开前后设备状态并记录有无保持、失能或报警，不从软件推断。要测“运动时断串口”的行为，另立专项规程；本计划不主动制造该情形。
